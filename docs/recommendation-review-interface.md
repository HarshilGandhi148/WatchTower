# Informational recommendation review

Approve and Disapprove record one immutable human review of a specific stored
validation report, snapshot and assessment round in `recommendation_reviews`.
Reviews remain in SpacetimeDB after the dashboard's rolling window clears them.
Public subscriptions show the committed state across browser tabs and reloads.
They review informational advice; they do not select a route or execute an aircraft
instruction. Operational controller actions retain the existing implementation gate.

The local Vite server exposes one bounded POST endpoint for this demo controller.
It accepts only loopback requests with an exact same-origin localhost Origin,
reads the existing root `.env` database URL/name/admin token privately, and calls
`review_recommendation`. Credentials never enter browser configuration or responses.
The database requires the administrator identity acting as this designated demo
review controller. Other identities cannot write reviews. This gateway is available
only in the local development server; public hosting requires its own authenticated
controller gateway.

The reducer checks current timestamps, snapshot, round and supersession, rejects
approval of integrity-invalid recommendations, and atomically records the first
review. Identical request IDs can retry even after expiry; conflicting decisions
cannot overwrite a committed review. Browser controls show success after the
database acknowledges the write, retain request IDs on retries, and disable while
pending, disconnected, superseded or reviewed. Replay never submits fixture reviews
to the live database. The schema addition preserves existing observation/report
tables; TypeScript bindings are regenerated by the pinned CLI.

Conversation summaries lead with retained observations and weather concerns.
Conditional hazards retain forecast/probability labels. Detailed coverage gaps and
original weather assessments remain available under evidence details. Missing data
is never converted into invented counts or clear weather.

At the user's request, this update is compiled and deployed without running tests.

Demo reports now alternate between monitoring and aircraft recommendations, aiming
for one recommendation cycle in two. Every displayed live recommendation names one
to three fresh observed aircraft from its immutable evidence snapshot. Two-minute
forecasts assume constant speed and track, are explicitly illustrative, and stay
separate from live observations and operational projection checks. Ground aircraft
or aircraft without motion fields receive a next-update watch recommendation.
No aircraft are invented to meet the display target. Reviewed cards disappear after
the database acknowledges the decision, and stay hidden through public subscription
updates and page reloads. Human-readable evidence leads with weather, nearby counts
and aircraft cards; identifiers and raw JSON are available under technical details.
